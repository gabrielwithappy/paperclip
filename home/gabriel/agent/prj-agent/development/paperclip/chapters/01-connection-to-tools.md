# 1장. 커넥터에서 에이전트 도구까지

## 연결했다고 바로 도구가 생기는 것은 아니다

Paperclip의 커넥터는 외부 서비스와의 접속을 관리한다. OAuth 인증이 완료되면 서버가 인증 정보를 보관한다.
에이전트가 이 연결을 쓰려면 회사 범위와 연결 접근 권한, 작업별 Allowed·Ask first·Off 정책을 통과해야 한다.
실행 중인 AI 도구가 그 MCP 서버를 등록하는 단계도 필요하다.

각 상태는 구분해서 읽는다. 저장된 연결은 구성의 존재를 뜻한다. 인증됨은 외부 계정 접근이 승인됐다는 뜻이다.
사용 가능은 현재 에이전트와 작업에 허용됐다는 뜻이고, 검증됨은 실제 필요한 도구 호출이 성공했다는 뜻이다.

## 책임의 경계

```text
외부 서비스 OAuth 인증
  → Paperclip의 인증 저장 및 회사·에이전트 권한 판정
  → 실행별 MCP 접속 정보 전달
  → 어댑터가 CLI의 MCP 설정에 적용
  → CLI에서 실제 도구 호출
  → Paperclip 게이트웨이의 권한·승인 검사
  → 외부 서비스 실행
```

서버의 테스트 화면에서 호출이 성공해도 어댑터 전달까지 검증된 것은 아니다. 반대로 CLI에 도구 이름이
보인다고 해서 어떤 작업이든 허용되는 것도 아니다. 실행 시 게이트웨이가 권한을 다시 검사한다.

`AdapterExecutionContext.runtimeMcp`는 서버 주소, 실행별 토큰, connectionId 등을 전달하는 계약이다.
외부 공급자의 OAuth 토큰을 에이전트에게 복사하는 용도로 사용하지 않는다.
`runtimeTools`는 connections_search·connection_request와 같은 연결 검색·설정 경로를 전달한다.
두 계약을 혼동하면 연결 검색은 되는데 실제 작업 도구는 보이지 않는 상황이 생길 수 있다.

## 사용자 설정 읽기

Any agent는 해당 회사의 에이전트가 연결에 접근할 수 있도록 하는 설정이다. 개별 작업 정책은 계속 적용된다.
Allowed는 승인 없이 실행, Ask first는 사람의 승인 후 실행, Off는 사용 차단이다.
외부 어댑터가 이 정책을 대신 판단하거나 완화해서는 안 된다.

도구가 없으면 우선 현재 연결 상태와 도구 전달을 확인한다. 새 OAuth 연결을 계속 만드는 것은 해결 절차가 아니다.
