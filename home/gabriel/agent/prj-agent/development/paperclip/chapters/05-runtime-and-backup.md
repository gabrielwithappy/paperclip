# 5장. 실행 환경과 인증 백업

## 호스트 로그인과 에이전트 로그인의 차이

Paperclip 에이전트는 호스트 터미널과 다른 HOME, XDG 경로, 환경변수를 받을 수 있다.
실행별 임시 HOME나 이전 컨테이너 경로가 남아 있으면 호스트에서 로그인에 성공한 CLI도 에이전트에서는 실패할 수 있다.
조사한 GWS 사례에서는 호스트의 현재 설정 폴더와 에이전트에 지정된 경로가 달랐다.

확인할 것은 실행 사용자, HOME, CLI 설정 디렉터리, 파일 존재와 읽기 권한이다.
환경변수 전체나 인증 파일 내용을 출력해 진단하지 않는다. 필요한 키의 존재·경로·인증 상태만 확인한다.
Paperclip 커넥터가 서버에 보관하는 OAuth와 별도 CLI의 로컬 OAuth도 구분한다.

## GWS에서 확인한 사실

기존 GWS 설정에는 삭제된 OAuth 클라이언트가 남아 있었다.
gcloud 실행 파일도 없었으나 기존 계정 설정은 남아 있었고, CLI 복구 후 접근 가능한 프로젝트를 확인했다.
새 클라이언트의 인증 JSON이 다운로드 폴더에 이미 존재해 이를 재사용했고 브라우저 승인 후 인증 상태가 유효해졌다.
Google Drive 읽기 호출도 성공했다. 이 결과는 그 호스트 환경의 검증이며 다른 HOME의 에이전트까지 보증하지 않는다.

Google Cloud Console의 화면과 secret 정책은 바뀔 수 있다. 다운로드나 Add Secret 버튼이 반드시 있다고
단정하지 않는다. 실제 유형과 현재 화면, 공식 문서, 저장된 JSON을 먼저 확인한다.

## 무엇을 백업할 것인가

클라이언트 JSON은 OAuth 앱 구성 정보다. 로그인 복원에는 refresh token이 담긴 암호화 credential과
복호화 키 등 CLI의 추가 로컬 상태가 필요할 수 있다. client JSON 하나와 전체 로그인 백업은 목적이 다르다.

GWS 설정 폴더를 백업할 경우 credential과 키가 함께 있을 수 있다.
백업 전체를 별도로 암호화하고 암호는 파일과 다른 위치의 비밀번호 관리자에 보관한다.
개별 에이전트의 권한이나 Paperclip 서버 vault를 임의 복제하는 것으로 이 백업을 확장하지 않는다.

개인 Google Drive는 파일별 비밀번호를 기본 제공하지 않는다. 편집 잠금은 내용을 숨기는 암호화와 다르다.
인증 백업은 업로드 전에 AES-256 암호화와 파일명 암호화를 지원하는 압축 도구로 보호하고 공유는 제한한다.
조직용 Workspace의 client-side encryption은 관리자 설정과 계정 조건이 있는 별도 기능이다.
