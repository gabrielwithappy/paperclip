# 3장. 외부 어댑터 플러그인의 적용 구조

## 이미 제공되는 확장 지점

Paperclip은 로컬 디렉터리나 npm 패키지에서 외부 어댑터를 설치할 수 있다.
패키지 루트의 createServerAdapter()가 ServerAdapterModule을 반환하고 서버 로더가 이를 등록한다.
같은 type을 반환하는 외부 어댑터는 내장 어댑터를 대체할 수 있다.

이번 후보는 opencode_local 타입을 유지하는 외부 패키지다. 기존 에이전트 설정을 다른 타입으로
직접 DB 수정할 필요는 없다. 대신 이 대체가 인스턴스 전체에 영향을 준다는 점을 고려해야 한다.
다른 회사에서 같은 타입을 쓰는 에이전트도 적용 대상이다.

이 확장은 self-hosted 환경을 대상으로 한다. Cloud-managed 환경은 임의의 외부 어댑터 코드 설치를 거부한다.
설치 기능이 있다는 사실과 이번 기능을 구현한 설치 가능 패키지가 존재한다는 사실도 구분한다.
현재 조사에서는 설치 구조를 확인했으며, 문제를 해결하는 새 패키지는 아직 만들지 않았다.

## OpenCode 플러그인과의 차이

OpenCode에도 자체 확장 기능과 MCP 설정이 있다. 그러나 Paperclip 외부 어댑터 플러그인은 Paperclip 서버가
에이전트 실행을 위임하는 확장이고, OpenCode 플러그인은 OpenCode 내부 동작을 확장한다.
이번 계획은 전자의 확장 지점을 사용한다.

어떤 방식이든 실행별 주소·토큰을 받아 현재 실행에 적용하는 연결 구현이 필요하다.
최신 OpenCode V2 문서를 조사 시점의 CLI 1.18.9에 그대로 적용하면 안 된다.
문법과 플러그인 API는 실제 설치 버전으로 확인한다.

## factory가 유지해야 하는 기능

외부 factory는 내장 정의 전체를 자동으로 상속하지 않는다. 실행 함수만 반환하면 기존 capability가 누락될 수 있다.
Local agent JWT, instructions bundle, skills 동기화, 모델 검색, runtime command spec과 session codec을 대조한다.
특히 supportsToolRefreshOnResume는 서버의 세션 준비 코드가 소비한다.
CLI가 실제로 갱신할 수 있는지 검증해 이 값을 선언해야 한다.

UI와 CLI는 기존 OpenCode 형식을 재사용할 수 있는지 확인한다. 필요한 경우에만 자체 완결 UI parser를 제공한다.
Codex·Claude의 설정 형식을 복사하거나, 기존 OpenCode 실행 코드를 통째로 복제하는 것은 기본 해법이 아니다.

## 설치 기록만으로 활성화를 증명할 수 없는 이유

외부 로더는 import나 factory 실패를 기록하고 해당 모듈을 건너뛸 수 있다.
재시작 때 내장 어댑터가 남으면 설치 기록은 있어도 MCP 기능은 적용되지 않은 상태가 된다.
API의 source 표시도 설치 레코드를 기준으로 하므로 그것만으로 실제 선택된 실행 구현을 증명하지 못한다.

외부 factory의 비밀 없는 build 진단과 실제 가짜 MCP 호출을 함께 확인해야 한다.
배포 전 격리 인스턴스, 재시작 후 확인, 내장 fallback 복원 절차를 계획에 포함한다.
